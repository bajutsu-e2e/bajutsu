# Additional git-secrets prohibited patterns beyond `git secrets --register-aws`.
# One extended-regex pattern per line; a leading `#` line is a comment. Registered into this
# clone's local git config by `make hooks` -> scripts/git-secrets-setup.sh. Keep this list narrow
# and specific to secrets this repo actually handles (see .env.example / SECURITY.md) — a broad
# pattern trades false positives for coverage it doesn't need.

# Anthropic API key / OAuth token (.env.example: ANTHROPIC_API_KEY, CLAUDE_CODE_OAUTH_TOKEN).
sk-ant-[A-Za-z0-9_-]{20,}

# A PEM private-key block pasted into a file or commit. No leading `-----`: a pattern starting
# with a hyphen gets misread as a command-line option (by `git secrets --add` and by the `grep`
# it shells out to), and the trailing dashes alone are already unambiguous. Also matches a GitHub
# App / GCS service-account private key: both are the same PEM format, just without the "RSA"
# classifier `[A-Z ]*` already tolerates.
BEGIN[A-Z ]*PRIVATE KEY-----

# A GitHub token (classic ghp_/gho_/ghu_/ghs_/ghr_ or fine-grained github_pat_). This repo
# integrates deeply with GitHub (bajutsu/github/app.py, the CI automation bot, MCP GitHub tools),
# and the prefix is distinctive enough that a false positive is essentially impossible. Open-ended
# `{36,}` / `{40,}`, not an exact count: git-secrets scans with `grep -w` (whole-word match), so an
# exact-length class that stops short of the token's actual end fails `-w` entirely (its right edge
# lands mid-word, not at a boundary) — open-ended always extends to the real word boundary.
(ghp|gho|ghu|ghs|ghr)_[A-Za-z0-9]{36,}
github_pat_[A-Za-z0-9_]{40,}

# BAJUTSU_SERVE_TOKEN / GRAFANA_ADMIN_PASSWORD hardcoded into a config file instead of passed via
# the environment (deploy/self-host/README.md's actual deploy-time secrets; the AWS provider above
# uses the same key=value shape for a value with no distinctive shape of its own). The trailing
# class is `[^[:space:]"']+`, not `[^\s"']+`: `\s` has no whitespace meaning inside a bracket
# expression (POSIX/GNU regex only expands it outside one) — there it's just the literal
# characters `\` and `s`, which silently breaks the match on any value containing the letter "s".
("|')?(BAJUTSU_SERVE_TOKEN|GRAFANA_ADMIN_PASSWORD)("|')?\s*(:|=>|=)\s*("|')?[^[:space:]"']+
