## はじめに

シナリオの `totp` ステップは、共有シークレットから時刻ベースのワンタイムパスワード（TOTP）を Request for Comments（RFC）6238 に従って計算し、そのコードを実行時変数へ一度だけ書き込みます。
この提案では、`totp` ステップがシークレットに名前を付けて登録できるようにします。
新しい `otp` ステップは、登録済みのジェネレータの名前を指定し、実行中の任意の時点で現在のコードを変数へ書き込みます。
シークレットを書き直す必要はありません。

## 動機

TOTP のコードは、時計の 30 秒の窓ひとつのあいだだけ有効です。
`totp` ステップ（[BE-0046](../BE-0046-otp-email-steps/BE-0046-otp-email-steps-ja.md)）は、実行された時点で時計を一度だけ読み、コードを `${vars.<var>}` に文字列として保存します。
`minRemaining` フィールド（[BE-0474](../BE-0474-totp-window-alignment/BE-0474-totp-window-alignment-ja.md)）は、その1つのコードを直後のステップが使い終えるまで有効に保ちます。
しかし、あとの時点でコードが必要なシナリオや、コードを何度も入力するシナリオでは、必要な箇所ごとに `totp` ステップ全体を繰り返すしかありません。
次のような流れが該当します。

- パスワード変更のような重要な操作のあとで、2つ目のコードを求めるサインインの流れです。
- サインアウトして再びサインインし、サインインのたびにコードを入力するシナリオです。
- コード入力欄の手前に遅い画面がいくつも並び、最初に生成したコードが入力欄へ届く前に失効する流れです。

`totp` ステップを繰り返すたびに、`secret` フィールドも書き直すことになります。
作成者は、シークレットをシナリオファイルにも証跡にも残さないようにする必要があります（[BE-0152](../BE-0152-totp-seed-artifact-leak/BE-0152-totp-seed-artifact-leak-ja.md)）。
そのため、写しが1つ増えるたびに、`${secrets.*}` を正しく経由させる箇所も1つ増えます。
繰り返しは意図も見えにくくします。
認証アプリは1つしかないのに、読み手には独立したジェネレータがいくつもあるように見えます。

2つの役割を分ければ、どちらの問題も解消します。
`totp` ステップはシークレットを持ち、名前を付けて一度だけ登録します。
`otp` ステップはそのジェネレータを名前で指し、実行された時点のコードを取得します。
この変更のあとは、複数の箇所でコードを入力するシナリオでも `secret` フィールドは1回だけで済みます。
各 `otp` ステップは、そのステップの実行時点で有効な窓のコードを書き込みます。

## 詳細設計

### `totp` ステップでジェネレータを登録する

`totp` ステップに、省略可能な `name` フィールドを追加します。
`name` を指定すると、ステップは解決済みのシークレットをその名前で登録し、シナリオの実行が終わるまで保持します。

```yaml
- totp: { secret: "${secrets.TOTP_SEED}", name: main, into: { var: code } }
```

`into` フィールドは省略可能にします。
これで、コードをまだ生成せずにジェネレータだけを登録できます。
ただし、`totp` ステップには `name` と `into` の少なくとも一方が必要です。
どちらも持たないステップは何もしないからです。
`minRemaining` フィールドの意味は変わりませんが、`into` を必須とします。
窓の待機は生成したコードを有効に保つためのものなので、登録だけのステップには待つ理由がありません。
モデルは、この2つの不正な形をどちらも読み込み時に拒否します。

ステップは、シークレットを登録する時点でその値を検証します。
同じ名前がすでに別のシークレットで登録されていれば、ステップは失敗します。
同じシークレットでの再登録は成功するので、`forEach` の中で `totp` を繰り返しても問題ありません。
base32 として不正なシークレットは、あとの `otp` ステップではなく `totp` ステップ自体を失敗させます。
メッセージは現在と同じで、シークレットを含みません。

### `otp` ステップ

新しい `otp` ステップは、登録済みのジェネレータを `from` で指定し、現在のコードを `into` へ書き込みます。

```yaml
- totp: { secret: "${secrets.TOTP_SEED}", name: main }
- tap: { id: auth.change_password }
# ... 任意の数のステップ ...
- otp: { from: main, into: { var: code }, minRemaining: 10 }
- type: { text: "${vars.code}", into: { id: auth.code } }
```

`otp` ステップは、`totp` と同じ `minRemaining` フィールドを受け付けます。
範囲は 1 から 30 までで、窓の待機も同じです。
そのため、生成したコードはアプリへ届けるステップが終わるまで有効なままです。
実行ログは、待機する `totp` ステップと同じ形で、このステップを `otp (≥10s left)` と表示します。

`from` の名前のジェネレータがまだ登録されていなければ、`otp` ステップはステップの失敗になります。
メッセージには、見つからなかったジェネレータの名前が入ります。
登録の順序は、ファイル上の順序ではなく実行の順序に従います。
実行されなかった `if` 分岐の中の `totp` ステップは、何も登録しません。

### 登録したシークレットの保持場所

実行中は、登録したシークレットをシナリオの実行時バインディングに保持します。
このバインディングは、解決済みの `${secrets.*}` の値をすでに保持している対応表です。
キーには `}` の文字を含めます。
`${...}` トークンの文法はこの文字を含められないので、シナリオのどのトークンからもこのキーには届きません。
そのため、作成者が登録済みのシークレットを `${...}` で読み出して、アプリへ入力できません。
ジェネレータの寿命はシナリオ実行のバインディングと同じです。
`if`、`forEach`、`group` の本体は同じジェネレータを共有し、次のシナリオはジェネレータのない状態から始まります。

`otp` ステップはシークレットを持たないので、`totp.secret` に対する既存の証跡のマスクは変更不要です。
シナリオのスナップショットには `from: main` が残ります。
生成されるコードは、`totp` がすでに `${vars.*}` へ書き込んでいるものと同じ短命な値です。

### 基本原則と codegen との関係

- **実行経路に大規模言語モデル（LLM）を置きません。** どちらのステップも、シークレットと時計だけからローカルに計算します。
- **決定性を保ちます。** `otp` ステップの待機は、`totp` がすでに使っている `minRemaining` の上限付きの条件待機だけです。ジェネレータが見つからないときは、推測した値を作らずにステップを失敗させます。
- **アプリに依存しません。** どちらのステップも Bajutsu のランナーの中で動き、どのバックエンドでも同じように振る舞います。
- **codegen は TODO を出力します。** `totp` と同様に、`otp` ステップには生成するテストでの対応物がありません。XCUITest、UI Automator、Playwright の出力は共通の補助関数を使い、ラベル付きの `// TODO` を書きます。この行はジェネレータと変数の名前を示し、シークレットは含めません。

## 検討した代替案

| 代替案 | 採らなかった理由 |
|---|---|
| 必要な箇所ごとに `totp` ステップを繰り返す | 現在でも動きますが、箇所ごとにシークレットを書き直すことになり、認証アプリが1つであることも見えにくくなります。 |
| `totp` ステップが書き込んだ変数名をキーにして、同じ変数へ再生成する | ジェネレータが1つの変数名に縛られます。古いコードと新しいコードのように、2つのコードを保持する流れを書けません。 |
| `${totp.main}` のような遅延評価のトークンで、展開時にコードを計算する | 時計を読む時点を示すステップがないので、レポートはコードを取得した時点を示せません。`minRemaining` の待機を付けるステップもありません。 |
| `totp.main` のような参照可能なキーにシークレットを保存する | `${totp.main}` というトークンが生のシークレットを入力欄へ差し込めてしまいます。リテラルのシークレットに対する証跡のマスクは、この経路を覆いません。 |
