## はじめに

Bajutsu の遮蔽は、書き出す側ごとの実装に委ねられています。
[`bajutsu/evidence/redaction.py`](../../bajutsu/evidence/redaction.py) の `Redactor` は、設定された
キー、ラベル、既知の秘匿値を隠します。evidence のサブシステムは、要素ツリー、デバイスログ、各
ネットワーク交換を書き出す前に `Redactor` を呼びます。しかし他の書き出し経路が同じことをするかは、
それぞれの実装者の心がけ次第です。そして `crawl` の成果物を書く経路は、呼んでいません。

本項目は、遮蔽を心がけから境界へ移します。run ディレクトリへの書き出しはすべて、redactor を必須と
する 1 つの出口を通ります。これにより、書き出す側の呼び忘れによって未遮蔽の成果物が出る経路は
なくなります。あわせて、呼び出し側が設定すべきでない 2 つの場合について遮蔽を既定で有効にします。
プラットフォーム自身が秘匿と印を付けたフィールドと、識別子またはラベルが資格情報を名指している
フィールドです。さらに書式による最後の網が、どのルールも名指していない値でも、見分けのつく資格情報の
書式を持つものを隠します。今回ディスクに達したのは、まさにこの場合でした。

具体的な流出が起点です。`crawl --guide ai` の実行が、`screenmap.json` と生成されたスクリーンマップ
レポートに `type settings.apikey='sk-ant-api03-…'` と書き出していました。値は合成で、API キーを求める
フィールドを満たすためにモデルが作ったもので、コミットには一度も入っていません。しかし運んだ機構は
実在します。この経路には遮蔽が 1 つもなく、しかもある関数が、設定されたどのルールも届かない場所へ値を
置いていました。

## 動機

### すでに保証されていること

現在の保証は複数の項目が積み上げたもので、それぞれ適用された場所では成り立っています。

- [BE-0032](../BE-0032-secret-variables/BE-0032-secret-variables-ja.md) は、シナリオに直値を書く
  代わりに `${secrets.X}` で秘匿値を束縛します。
- [BE-0130](../BE-0130-default-network-secret-redaction/BE-0130-default-network-secret-redaction-ja.md)
  は、資格情報を運ぶヘッダの集合を既定で隠します。シナリオが `redact:` を書かなかっただけで
  `network.json` が生きたトークンを渡すことはありません。既定を解除するには、明示的で目に見える
  `redact.unmaskHeaders` が必要です。
- [BE-0153](../BE-0153-encode-aware-secret-redaction/BE-0153-encode-aware-secret-redaction-ja.md) は、
  既知の秘匿値をよくある符号化形でも隠します。パーセント符号化されたトークンは、そのままの形では
  現れないからです。
- [BE-0120](../BE-0120-recorded-scenario-secret-tokenization/BE-0120-recorded-scenario-secret-tokenization-ja.md)
  は、`record` 中に作成エージェントが入力した秘匿値を `${secrets.*}` へトークン化し、下書きシナリオへ
  直値を書きません。
- [BE-0047](../BE-0047-ai-data-sovereignty/BE-0047-ai-data-sovereignty-ja.md) と
  [BE-0097](../BE-0097-crawl-ai-data-sovereignty/BE-0097-crawl-ai-data-sovereignty-ja.md) は、AI
  プロバイダへ送るテキスト入力を遮蔽します。作成系の経路と `crawl --guide ai` の経路が対象です。
- [BE-0151](../BE-0151-screenshot-secret-capture-warning/BE-0151-screenshot-secret-capture-warning-ja.md)
  は、スクリーンショットを隠せないことを事前に警告します。ピクセルが守られていると匂わせません。

これらはすべて `Implemented` です。どれも確立していないのは、**新しく書き出す経路がこの保証を
引き継ぐ**という性質です。

### 足りないのは設定ではなく強制

`crawl` は遮蔽に必要なものをすでに持っています。コマンドは解決済みのターゲット設定と環境の秘匿値から
redactor を組み立て（[`bajutsu/cli/_shared.py:137`](../../bajutsu/cli/_shared.py)）、AI guide へ渡して
送信するプロンプトを洗っています。その redactor を自分の成果物を書く経路へは渡していません。
[`bajutsu/crawl/serialize.py`](../../bajutsu/crawl/serialize.py)、
[`bajutsu/crawl/report.py`](../../bajutsu/crawl/report.py)、
[`bajutsu/cli/commands/crawl.py`](../../bajutsu/cli/commands/crawl.py) に、遮蔽への参照は 1 つも
ありません。つまり BE-0097 は `crawl` がモデルへ送るものを守り、`crawl` がディスクへ書くものを未保護の
まま残しました。しかも書き出すレポートは、共有を前提とした自己完結の HTML ファイルです。

より広く見れば、1 回の実行のバイト列が通る場所は 1 つに定まっていません。書き出しは
`Path.write_text` や `json.dumps` の直接呼び出しとして、コマンドの各モジュール、crawl のパッケージ、
レポートの描画に散らばっています。書き出す経路を増やすことは、遮蔽するかしないかが決まっていない経路を
増やすことであり、どちらを選んだのかを実装者に知らせるものもありません。

### 設定されたどのルールも届かない場所に値を置く関数

redactor が値を隠す方法は 3 つあります。設定されたキーの後ろ、要素のラベルが設定されている場合、値が
既知の秘匿直値と一致する場合です。crawl のアクションは 3 つすべてをすり抜けます。
[`bajutsu/crawl/core.py:145`](../../bajutsu/crawl/core.py) はアクションの表示名を
`f"type {what}={self.value!r}"` として組み立てるので、入力したテキストが自由文へ埋め込まれ、スクリーン
マップの各ノードと各エッジの `action` フィールドとして直列化されます。

設定されたどのルールも、ここには届きません。値はネットワークヘッダではないので既定のヘッダ集合は
適用されません。文字列は要素ではないのでラベルによる遮蔽も適用されません。そして AI guide が作った値は
既知の秘匿直値ではありません。`${secrets.X}` で束縛されたことがなく、探索の途中で crawl が作り出した値
だからです。値を事前に知っていることに依存する遮蔽ルールは、ツール自身が生成する値を覆えません。

### ヘッダ以外の遮蔽は既定では働かない

`Redactor.active` が真になるのは、キー、ラベル、既知の値のいずれかが設定されているときだけです。1 つも
設定されていない実行では、`redact_text` と `redact_elements` は入力をそのまま返します。ヘッダの遮蔽は
意図的な例外で、BE-0130 がこれを既定で有効にした理由は、ここで当てはまる理由と同じです。誰かが求めた
ときだけ現れる保護は、もっとも必要な実行では存在しない保護になります。`crawl` にはそもそもシナリオが
ないので `redact:` ブロックを持つことがなく、redactor を配線したあとでも要素と自由文の遮蔽はこの経路で
働きません。

同じ不作動は実在のパスワード欄にも及びます。残っているローカルの実行には
`type auth.password='Passw0rd!2026'` がそのまま書かれています。プラットフォームはそのフィールドを
`secureTextField` と印付けしていたので、秘匿性は取得の時点で判明していました。設定を要求する必要は
ありませんでした。

## 詳細設計

### 境界

run ディレクトリへの書き出しを 1 つの出口が所有します。呼び出し側はパスと内容を渡し、出口が実行の
redactor を適用して書きます。この出口が run ディレクトリへ書く唯一のコードなので、遮蔽は呼び出し側の
心がけではなく、書き出す場所の性質になります。

隠せない内容のために、出口はバイト列も受け取ります。スクリーンショット、動画、アーカイブが該当し、
未遮蔽で書いたことを記録します。これは
[BE-0151](../BE-0151-screenshot-secret-capture-warning/BE-0151-screenshot-secret-capture-warning-ja.md)
の正直さを保つためで、画像が守られているとは主張しません。

境界はテストで強制します。run の出力を書くモジュールの抽象構文木を走査し、出口の外で run ディレクトリの
パスに対する `write_text`、`write_bytes`、`open` の直接呼び出しがあれば落とします。この検査は機械的で
モデルを必要としないので、ゲートに入れられます。

### 設定を必要としない遮蔽

BE-0130 のヘッダ集合に 2 つの既定が加わります。どちらも `redact.unmaskHeaders` が確立した、明示的で
目に見える解除の形を取ります。

**プラットフォームが秘匿と印を付けたフィールド。** `secureTextField` の trait を持つ要素は値を隠し、
そうしたフィールドを狙う入力や一括入力の値は、そのアクションを記録するどの成果物でも隠します。
フィールドの秘匿性はプラットフォームがすでに述べているので、設定ファイルが言い直す必要はありません。

**識別子またはラベルが資格情報を名指しているフィールド。** 既定の語彙として `password`、`passwd`、
`secret`、`token`、`apikey`、`api_key`、`credential`、`otp`、`pin` を、要素の識別子とラベルに対して
大文字小文字を無視し語の境界で照合します。`settings.apikey` を隠したはずの既定がこれです。語彙は
巧妙にせず小さく保ち、文書に載せます。作成者が予測できないルールは、作成者が頼れないルールだから
です。

### ツール自身が生成する値

既知の秘匿値を鍵にする遮蔽ルールは、Bajutsu 自身が作った値を覆えません。AI guide が現実的な API キーを
作るときがまさにそれです。この種類に対して 2 つの変更を加えます。

1 つめは、入力値を人間向けの文字列へ埋め込むのをやめることです。`Action.describe` は `type <target>`
だけを出し、値はアクション自身の `value` フィールドに残します。これにより値を書くかどうかを決める場所が
1 つになり、出口のルールが届きます。スクリーンマップは再実行可能なアクションを保ちます。`perform` は
すでに `value` を直接読んでおり、表示名を解析していないからです。

2 つめは、出口がテキストを書く前に書式の網をかけることです。見分けのつく資格情報の書式は、どこに
現れても隠します。Anthropic のキーの `sk-ant-`、AWS のアクセスキー id の `AKIA`、GitHub のトークンの
`gh[pousr]_`、3 区画からなる JSON Web Token（`JWT`）、`PEM` の秘密鍵ヘッダです。一致した値は隠し、
成果物を名指す警告として報告します。網まで到達した値は、手前のルールが捕まえるべきだったことを意味する
からです。書式は素の正規表現なので、モデルは介在せず、プライムディレクティブ 1 に触れません。

### 保証しないこと

本項目は、秘匿値が成果物へ到達することを不可能にはしません。そう書けば偽になります。残る 3 つを、
覆い隠さずに名指します。

- **ピクセルは隠れません。** 入力済みのパスワード欄を写したスクリーンショットには、値が写ったまま
  です。BE-0151 がすでに警告を確立しており、本項目はそれを変えません。
- **印のないフィールドの任意の値は生き残りえます。** プラットフォームが印を付けず、識別子とラベルに
  資格情報らしい語もなく、`${secrets.X}` で束縛されたこともない値を考えます。その書式が網のどの型にも
  一致しなければ、ふつうのテキストと区別できません。見分けるには意味の判断が必要で、プライムディレクティブ 1 が
  この経路から遠ざけています。
- **網の語彙は有限です。** 誰も型を追加していない資格情報の書式は、網を通り抜けます。

本項目が保証するのは、もっと狭く、しかも検査できることです。書き出す側が遮蔽を迂回できないこと、
秘匿性が取得の時点で判明する 2 つの場合が設定なしで隠れること、見分けのつく資格情報の書式がどこに
現れても隠れることです。上の残余は文書に載せるので、運用者は成果物を共有したあとではなく共有する前に
判断できます。

### 作業分解（`MECE`）

相互に排他かつ全体として網羅的（Mutually Exclusive, Collectively Exhaustive、`MECE`）な作業単位は
次のとおりです。

1. **run ディレクトリの出口**

   run の出力に対する唯一の書き出し経路を導入し、実行の `Redactor` を受け取ってテキスト内容へ適用
   します。画像、動画、アーカイブのために未遮蔽バイト列の明示的な入口を設け、未遮蔽で書いたことを
   記録します。

2. **既存の書き出しをすべて出口へ通す**

   コマンドの各モジュール、crawl のパッケージ、レポートの描画にある直接の書き出しを変換します。既知の
   箇所には [`bajutsu/cli/commands/crawl.py`](../../bajutsu/cli/commands/crawl.py)、
   [`bajutsu/crawl/report.py`](../../bajutsu/crawl/report.py)、
   [`bajutsu/crawl/flows.py`](../../bajutsu/crawl/flows.py)、run のアーカイブ書き出しが含まれます。
   evidence のサブシステムの挙動は変わりません。すでに遮蔽しており、1 つのルールで全体を覆うために
   出口へ移すだけです。

3. **境界のテスト**

   出口の外で run ディレクトリのパスへ書くモジュールがあれば落とす抽象構文木の検査を追加し、将来の
   書き出しが黙って遮蔽を迂回できないようにします。ゲートに配線します。

4. **プラットフォームが秘匿と印を付けたフィールドの既定遮蔽**

   `secureTextField` の要素の値と、そうしたフィールドを狙う入力や一括入力の値を、設定なしで隠します。
   `redact.unmaskHeaders` と並ぶ、目に見える解除の形を追加します。

5. **資格情報を名指す識別子またはラベルの既定遮蔽**

   文書に載せた既定の語彙を、要素の識別子とラベルに対して照合します。解除の形は同じです。crawl の
   アクション経路も覆い、そうしたフィールドを狙うアクションがスクリーンマップで隠れるようにします。

6. **アクションの表示名から値を外す**

   [`bajutsu/crawl/core.py`](../../bajutsu/crawl/core.py) を変更し、`Action.describe` が値を含めずに
   対象だけを述べるようにして、値はアクション自身のフィールドに残します。再実行に影響がないことを
   確かめます。`perform` は表示名ではなくフィールドを読んでいます。

7. **書式による網**

   出口が書くテキストで、見分けのつく資格情報の書式を隠し、成果物を名指して警告します。書式は素の
   正規表現のまま、文書に載せた 1 箇所へ置きます。

8. **テスト**

   既定の遮蔽ルールそれぞれ、crawl のアクションが表示名へ値を運ばないこと、網が各書式を隠して一度だけ
   警告すること、出口の未遮蔽バイト列の経路が書いた内容を記録すること、そして FakeDriver 上の `crawl`
   の実行で、資格情報を名指すフィールドとプラットフォームが印を付けたフィールドの平文の値がスクリーン
   マップに存在しないことを網羅します。

9. **ドキュメント**

   2 つの新しい既定、その解除、網、3 つの残余を [`docs/evidence.md`](../../docs/evidence.md) とその
   日本語版に、BE-0130 のヘッダの既定の隣へ書きます。何を守り何を守らないのかを明確に述べます。
   運用者はその記述をもとにレポートを共有するかを決めるからです。

### プライムディレクティブの遵守

- **AI は判定しない**

  どのルールも、設定された名前、trait、語境界の照合、素の正規表現のいずれかです。モデルは介在せず、
  `run` の判定にも触れません。

- **決定性優先**

  遮蔽は内容と解決済み設定の純関数なので、同じ実行は同じ成果物のバイト列を生みます。境界のテストは
  機械的です。固定の `sleep` や条件待ちは関与しません。

- **アプリ非依存**

  既定はプラットフォームの trait と、識別子およびラベルのテキストを鍵にし、特定のアプリを鍵にしません。
  アプリごとの追加は、遮蔽の設定がすでに置かれている `targets.<name>.redact` に留まります。

## 検討した代替案

- **既存の redactor を crawl の書き出しへ配線して終わりにする**

  全体の答としては却下しました。Unit 2 はこれを含みます。今日流出している経路は直りますが、次に増える
  書き出しは無防備なままです。新しい直接の `write_text` を止めるものがないからです。しかも
  `settings.apikey` は隠せませんでした。redactor は設定がなければ働かず、crawl は `redact:` ブロックを
  持たず、値は束縛されたのではなく作られたものだからです。

- **`Action.describe` の中で値を隠す**

  却下しました。整形する場所で隠す判断を持つと、次に整形を書く場所で同じ判断をやり直すことになります。
  文字列から値を外せば、統制すべきフィールドは 1 つだけ残ります。こちらのほうが面は小さくなります。

- **実行中に遮蔽せず、実行後に gitleaks で成果物を走査する**

  主たる機構としては却下しました。今回の流出を浮かび上がらせたのは実行後の走査なので、検出はよく
  効きます。しかしその時点で平文はディスクにあり、すでに共有されている可能性もあります。走査は、
  チェックサムが参照されているかもしれない成果物を書き換えなければ、その場で隠せません。検出が
  確実に止めるには、指摘で実行を失敗させる必要があります。それは走査器を判定の経路へ置くことです。
  書式の型という発想は、バイト列が着地する前という有効な位置で Unit 7 が引き受けます。

- **run ディレクトリを遮蔽せず暗号化する**

  却下しました。暗号化は保存時の成果物を守りますが、読むため、共有するため、PR へ添付するために復号
  された時点では何もしません。そこがまさに問題になる瞬間です。さらに、evidence のサブシステムと
  `serve` の UI が依存している素のファイルとしての参照を壊します。

- **秘匿値が束縛されているときは成果物を書かない**

  却下しました。evidence は失敗を説明するために存在します。資格情報を束縛する実行で成果物を出さない
  ことは、調査がもっとも難しいところで診断を取り上げることになります。遮蔽なら、成果物の構造を保った
  まま値だけを取り除けます。

- **値が機密に見えるかどうかをモデルに尋ねる**

  即座に却下しました。実行について何を書くかを決める経路にモデルを置くことになり、成果物のバイト列が
  非決定的になり、プライムディレクティブ 1 は `run` の経路がモデルの判断に依存することを禁じています。
