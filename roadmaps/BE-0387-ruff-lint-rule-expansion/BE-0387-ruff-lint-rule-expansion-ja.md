## はじめに

`pyproject.toml` は ruff の linter に対して `ANN B C4 DTZ E F I N PERF PIE PT RUF S SIM T20 UP` を
選択しており、これは1つずつギャップを閉じる形で積み上げてきたものです。直近では
[BE-0067](../BE-0067-code-quality-gate-hardening/BE-0067-code-quality-gate-hardening-ja.md) が
flake8-bandit のルール群である `S` を追加しました。flake8 が別プラグインで提供している分類のうち、
いくつかはまだこの選択の外にあります。本項目は、そのなかから厳選した分類を加えます。追加するのは
`PTH`（`os.path` に代えて pathlib を使う）、`RET`（return 文の一貫性）、`ARG`（未使用の引数）、
`SLF`（クラスの外からの private メンバーアクセス）です。ここに `W`（`E` の姉妹にあたる
pycodestyle の warning で、これまで有効にしていませんでした）と `PLE`（Pylint の error 層で、
ruff が直接再実装しているものです）、
そして `TRY`（例外処理のスタイル）と `PLW`（Pylint の warning 層）から厳選した一部を加えます。
これは、BE-0067 が単体の Bandit 導入ではなく ruff の `S` ルールを使ったことと整合するもので
あり、典型的な flake8 + Pylint 構成に対して本リポジトリの静的解析がまだ残しているギャップの
残り部分に適用します。

## 動機

`make lint` は `ruff check .` をリポジトリ全体に対して実行するため
（[Makefile:93-94](../../Makefile)）、`tests/`・`demos/`・`scripts/` も `bajutsu/` と同じルール
選択の対象になり、免除されません。候補となる各分類を `bajutsu/` だけに対して実行すると、扱いやすく、
しかもほとんどが意味のある指摘であることがわかります。`W` は0件（コストなしで有効化できます）、
`RET` は2件、`PTH` は17件、`SLF` は38件、`ARG` は130件、`TRY` は468件です。ただし、この
`bajutsu/` だけの測定はリポジトリ全体のコストを過小に見せています。`ARG` だけで `tests/` に対して
1,406件の指摘が出ており、これは `bajutsu/` の130件の10倍以上です。理由は、フィクスチャやモックの
未使用引数が pytest の通常のパターンであるためで、これは本項目が後述する `SLF` の tests-ignore
について挙げている根拠と同じです。`TRY` の件数は1つのルールに偏っています。`TRY003`
（468件中438件）は、メッセージが数語より長い `raise` をすべて検出するもので、これは Pylint 由来の
ヒューリスティックであり、実務上は過剰と広く見なされています。具体的なエラーメッセージこそが
`raise` の要点であることが多く、それ自体は smell ではないためです。残る3つの `TRY` ルールは、
小規模で精度の高い集まりです。`try` の成功時にだけ走るコードを `else` ブロックにまとめるよう
勧める `TRY300`（17件）、単なる `ValueError` より `TypeError` を使うべき型誤り検出を勧める
`TRY004`（10件）、そして `except` ブロック内で `logging.error` より `logging.exception` を使うべき
と勧める `TRY400`（3件、トレースバックをログに残せます）です。`ARG` の130件は、`ARG002`
（94件、未使用のメソッド引数。あるバックエンドでは `Driver` の Protocol 実装がすべての引数を
必要としない場合が多いです）、`ARG001`（20件、未使用の関数引数）、`ARG005`（16件、未使用の
lambda 引数）に分かれます。

Pylint のルール群の残りを ruff の `PL` プレフィックスから取り込むかどうかは、本項目が扱わない別の
問題です。`PL` を全体で実行すると526件が検出され、そのうち `PLC0415`（トップレベル外での
import）だけで258件を占めます。本リポジトリ自身の慣習は、重い依存やオプションの依存を必要と
する関数の内側で遅延 import することであり（`boto3` や `playwright` などに対する mypy のオーバーライドが
すでにこの慣習を記録しています）、ここでは `PLC0415` は偽陽性の多い結果になります。実際のバグに
もっとも近い層である Pylint の error 層 `PLE` は0件です。そこで本項目は、`W` と同じ「コストなしで
有効化できる」という根拠にもとづいて `PLE` も採用します。今すぐの移行コストはかからず、そのうえ
`raise` の置き場所の誤り（`PLE0704`）、`async` 関数の外での `await`（`PLE1142`）、`strip` への
不正な引数（`PLE1310`）など、今後発生する `PLE` のエラーをこれから先ずっと検知できるように
なります。本項目が取り込む `PLW` の一部——`global` 文を指す
`PLW0603`（7件）、ループ変数がそのループ内で上書きされることを指す `PLW2901`（3件）、
`check=` を明示しない `subprocess.run` 呼び出しを指す `PLW1510`（3件）——は、`PLC0415` の雑音を
除いたあとに残る、意味のある部分です。`PL` のさらに別の一部である関数サイズの
ルール群 `PLR0911` / `PLR0912` / `PLR0915` は、複雑度のしきい値が測るものと同じもの、つまり1つの
関数がどれだけ大きく枝分かれしているかを測っており、スタイルの問題ではないため、ここではなく本項目
と同時に提案している複雑度上限の項目に属します。

## 詳細設計

8つの分類を `[tool.ruff.lint]` の `select` リストへ加えます。レビューが1つのルールの修正だけを
見比べられるよう、各分類は別々のコミットとして landing します。

- **`W`**: 追随作業なしで追加します。今日の時点で0件です。
- **`PLE`**: 追随作業なしで追加します。今日の時点で0件です。
- **`RET`**: 追加し、修正をそのまま適用します。`bajutsu/` の2件と `tests/` の4件を合わせて6件で、
  そのうち4件は `--fix` で対応できます。
- **`PTH`**: 追加し、`bajutsu/` の17件、`tests/` の6件、`demos/`・`scripts/` の3件を合わせた26件を
  修正します。それぞれ `os.path` の呼び出しを同等の `pathlib.Path` のメソッドへ置き換えるもので、
  新しいコードで本リポジトリがすでに好んでいる書き方と揃います。
- **`SLF`**: 追加し、すでにある `ANN` / `T20` / `S` の無視設定に揃えて `tests/**` では無視します
  （フィクスチャやフェイクの private な状態へテストが入り込んで検証するのは、smell ではなく通常の
  パターンです）。そのうえで `bajutsu/` 自体にある38件を修正します。アクセスが正当な箇所では狭い
  公開アクセサを設け、そうでない箇所ではアクセスを持ち主のクラスの内側に移します。
- **`ARG`**: 追加し、上記の `SLF` の無視設定に揃えて `tests/**` でも無視します（未使用のフィクス
  チャやモックの引数は smell ではなく pytest の通常のパターンです）。そのうえで `bajutsu/` にある
  130件を原因ごとに切り分けます。あるバックエンドで `Driver` の Protocol メソッドが正当な理由で
  引数を使わない場合はその引数を残し、どの Protocol を満たすためかを名指すコメント付きの
  `# noqa: ARG002` を添えます。実際の値で呼ぶ箇所がどこにもない引数は削除します。
- **`TRY`**: 追加し、`TRY003` はファイル単位ではなくグローバルな `ignore` リストへ入れます（この
  ルールはこのコードベースに限らずどこでも雑音になるためです）。残る `TRY300` / `TRY004` /
  `TRY400` は修正します。
- **`PLW`**: 追加し、`PLW0603` は1件ずつ判断します。意図的なモジュール単位のキャッシュのために
  使っている `global` はコメントを添えて残し、実質的にリファクタ漏れであるものは修正します。より
  件数の少ない `PLW2901` / `PLW1510` は直接修正します。`bajutsu/` の外では `tests/` に13件の残り
  （`PLW0108`（不要な lambda）8件と `PLW1510` 5件）があり、同じように修正します。`PLW0108` は
  lambda をそれが包んでいる関数や式に置き換えることで直します。

`tests/**` と `demos/**` は、`ANN`・`T20`・`S` に対するすでにある一括無視をそのまま保ちます
（[pyproject.toml](../../pyproject.toml)）。本項目はそれらを狭めません。`scripts/**` も
`T20` / `S607` の無視をそのまま保ちます。landing 前に `bajutsu/`・`tests/`・`demos/`・`scripts/`
の4つのツリーすべてに対して8つの分類を測定した結果、`tests/**` には上記の理由により `SLF` と
`ARG` という2つの新しい一括無視が必要だとわかりました。`bajutsu/` の外で見つかった `PTH`・
`RET`・`PLW` の小さな残りは、上の各項目で説明したとおり、無視ではなく修正します。`demos/**` と
`scripts/**` には新しい一括無視は必要ありません。

## 検討した代替案

- **`PL` プレフィックス全体を採用する** — 却下します。`PLC0415` だけで526件中258件を占め、本
  コードベースの遅延 import という意図的な慣習にほぼ全面的に反しています。本項目のように `PLE` を
  独自のプレフィックスで選択すれば、この雑音を抱え込まずに、持つ価値のある層だけを取り込めます。
- **ruff と並べて専用の Pylint、Dlint、あるいは `hacking` を導入する** — 却下します。これは、
  BE-0067 が専用の Bandit 導入ではなく ruff の `S` を選んだことと整合するものです。ruff はそれぞれ
  の有用な部分をすでに再実装しており（Pylint のルール群に対する `PL*`、そして Dlint が加えるはずのセキュリティ lint
  の役割はすでに `S` が担っています）、2つ目のツールを入れてもゲート自身の linter を重複させる
  だけで、実際のギャップを埋めることにはなりません。`hacking` は OpenStack のプロジェクト規約を
  対象としたものであり、ここには当てはまりません。
- **`TRY003` を有効にして呼び出し箇所ごとに抑制する** — 却下します。438件では、呼び出し箇所ごとの
  `# noqa` が、それが説明するはずの例外送出コードの件数を上回ってしまいます。理由を書いたコメント
  付きでルールそのものを1か所で抑制するほうが、雑音なしに同じ判断を伝えられます。
- **`ARG002` の指摘をリポジトリ全体のアンダースコア接頭辞の慣習（`_backend_specific_arg`）へ
  まとめる** — 却下します。あるバックエンドが無視している Protocol の引数すべてをリネームする
  と、見た目だけの変更のために実装のシグネチャすべてに手を入れることになります。その引数を使わない
  実装1か所に絞った `# noqa` のほうが小さく、その場で理由を示せます。
