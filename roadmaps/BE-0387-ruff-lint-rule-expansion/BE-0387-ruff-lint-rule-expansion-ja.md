## はじめに

`pyproject.toml` は ruff の linter に対して `ANN B C4 DTZ E F I N PERF PIE PT RUF S SIM T20 UP` を
選択しています。この一覧は、1つずつギャップを閉じる形で積み上げてきたものです。直近では
[BE-0067](../BE-0067-code-quality-gate-hardening/BE-0067-code-quality-gate-hardening-ja.md) が
flake8-bandit のルール群である `S` を追加しました。flake8 が別プラグインで提供している分類のうち、
いくつかはまだこの選択の外にあります。

本項目は、そのなかから厳選した分類を加えます。追加するのは `PTH`（`os.path` に代えて pathlib を
使う）、`RET`（return 文の一貫性）、`ARG`（未使用の引数）、`SLF`（クラスの外からの private メンバー
アクセス）です。ここに `W`（`E` の姉妹にあたる pycodestyle の warning で、これまで有効にしていません
でした）と `PLE`（Pylint の error 層で、ruff が直接再実装しているものです）を加えます。そして `TRY`
（例外処理のスタイル）と `PLW`（Pylint の warning 層）から厳選した一部も加えます。

この選び方は、BE-0067 が単体の Bandit 導入ではなく ruff の `S` ルールを使ったことと整合します。
典型的な flake8 + Pylint 構成に対して本リポジトリの静的解析がまだ残しているギャップの残り部分に、
同じ方針を適用します。

## 動機

`make lint` は `ruff check .` をリポジトリ全体に対して実行します（[Makefile:93-94](../../Makefile)）。
そのため `bajutsu/` を縛るルール選択は、`tests/`・`demos/`・`scripts/` も免除なしで縛ります。

候補となる各分類を `bajutsu/` だけに対して実行すると、扱いやすく、しかもほとんどが意味のある指摘
であることがわかります。

`W` は0件です（コストなしで有効化できます）。`RET` は2件、`PTH` は17件、`SLF` は38件、`ARG` は130件、
`TRY` は468件です。

ただし、この `bajutsu/` だけの測定は、リポジトリ全体のコストを過小に見せています。`ARG` だけで
`tests/` に対して1,406件の指摘が出ており、これは `bajutsu/` の130件の10倍以上です。理由は、
フィクスチャやモックの未使用引数が pytest の通常のパターンであるためです。これは、本項目が後述する
`SLF` の tests-ignore について挙げている根拠と同じです。

`TRY` の件数は1つのルールに偏っています。`TRY003`（468件中438件）は、メッセージが数語より長い
`raise` をすべて検出します。これは Pylint 由来のヒューリスティックで、実務上は過剰と広く見なされて
います。具体的なエラーメッセージこそが `raise` の要点であることが多く、それ自体は誤りではないため
です。残る3つの `TRY` ルールは、小規模で精度の高い集まりです。

`TRY300`（17件）は、`try` の成功時にだけ走るコードを `else` ブロックにまとめるよう勧めます。
`TRY004`（10件）は、型誤りの検出に単なる `ValueError` より `TypeError` を使うよう勧めます。
`TRY400`（3件）は、`except` ブロック内で `logging.error` より `logging.exception` を使うよう勧めます。
トレースバックをログに残せます。

`ARG` の130件は、3つに分かれます。`ARG002`（94件）は、未使用のメソッド引数です。あるバックエンドでは
`Driver` の Protocol 実装がすべての引数を必要としない場合が多くあります。`ARG001`（20件）は、未使用の
関数引数です。`ARG005`（16件）は、未使用の lambda 引数です。

Pylint のルール群の残りを ruff の `PL` プレフィックスから取り込むかどうかは、本項目が扱わない別の
問題です。`PL` を全体で実行すると526件が検出され、そのうち `PLC0415`（トップレベル外での import）
だけで258件を占めます。本リポジトリ自身の慣習は、重い依存やオプションの依存を必要とする関数の内側で
遅延 import することです（`boto3` や `playwright` などに対する mypy のオーバーライドがすでにこの慣習を
記録しています）。そのため、ここでは `PLC0415` は偽陽性の多い結果になります。

実際のバグにもっとも近い層である Pylint の error 層 `PLE` は0件です。そこで本項目は、`W` と同じ
「コストなしで有効化できる」という根拠にもとづいて `PLE` も採用します。今すぐの移行コストはかから
ず、今後発生する `PLE` のエラーをこれから先ずっと検知できるようになります。たとえば、`raise` の
置き場所の誤り（`PLE0704`）、`async` 関数の外での `await`（`PLE1142`）、`strip` への不正な引数
（`PLE1310`）です。

本項目が取り込む `PLW` の一部は、`PLC0415` の雑音を除いたあとに残る、意味のある部分です。
`PLW0603`（7件）は `global` 文を指します。`PLW2901`（3件）は、ループ変数がそのループ内で上書きされる
ことを指します。`PLW1510`（3件）は、`check=` を明示しない `subprocess.run` 呼び出しを指します。

`PL` のさらに別の一部である関数サイズのルール群 `PLR0911` / `PLR0912` / `PLR0915` は、ここではなく、
本項目と同時に提案している複雑度上限の項目に属します。これらのルールは、複雑度のしきい値が測るものと
同じもの、つまり1つの関数がどれだけ大きく枝分かれしているかを測っており、スタイルの問題ではない
ためです。

## 詳細設計

8つの分類を `[tool.ruff.lint]` の `select` リストへ加えます。レビューが1つのルールの修正だけを
見比べられるよう、各分類は別々のコミットとして landing します。

- **`W`**: 追随作業なしで追加します。今日の時点で0件です。
- **`PLE`**: 追随作業なしで追加します。今日の時点で0件です。
- **`RET`**: 追加し、修正をそのまま適用します。`bajutsu/` の2件と `tests/` の4件を合わせて6件で、
  そのうち4件は `--fix` で対応できます。
- **`PTH`**: 追加し、`bajutsu/` の17件、`tests/` の6件、`demos/`・`scripts/` の3件を合わせた26件を
  修正します。それぞれ `os.path` の呼び出しを同等の `pathlib.Path` のメソッドへ置き換えるもので、
  新しいコードで本リポジトリがすでに好んでいる書き方と揃います。
- **`SLF`**: 追加し、すでにある `ANN` / `T20` / `S` の無視設定に揃えて `tests/**` では無視します。
  フィクスチャやフェイクの private な状態へテストが入り込んで検証するのは、誤りではなく通常の
  パターンだからです。そのうえで `bajutsu/` 自体にある38件を修正します。アクセスが正当な箇所では
  狭い公開アクセサを設け、そうでない箇所ではアクセスを持ち主のクラスの内側に移します。
- **`ARG`**: 追加し、上記の `SLF` の無視設定に揃えて `tests/**` でも無視します。未使用のフィクス
  チャやモックの引数は誤りではなく pytest の通常のパターンだからです。そのうえで `bajutsu/` に
  ある130件を原因ごとに切り分けます。あるバックエンドで `Driver` の Protocol メソッドが正当な理由で
  引数を使わない場合は、その引数を残し、どの Protocol を満たすためかを名指すコメント付きの
  `# noqa: ARG002` を添えます。実際の値で呼ぶ箇所がどこにもない引数は削除します。
- **`TRY`**: 追加し、`TRY003` はファイル単位ではなくグローバルな `ignore` リストへ入れます。この
  ルールはこのコードベースに限らずどこでも雑音になるためです。残る `TRY300` / `TRY004` /
  `TRY400` は修正します。
- **`PLW`**: 追加し、`PLW0603` は1件ずつ判断します。意図的なモジュール単位のキャッシュのために
  使っている `global` はコメントを添えて残し、実質的にリファクタ漏れであるものは修正します。より
  件数の少ない `PLW2901` / `PLW1510` は直接修正します。`bajutsu/` の外では `tests/` に13件の残り
  （`PLW0108`（不要な lambda）8件と `PLW1510` 5件）があり、同じように修正します。`PLW0108` は
  lambda をそれが包んでいる関数や式に置き換えることで直します。

`tests/**` と `demos/**` は、`ANN`・`T20`・`S` に対するすでにある一括無視をそのまま保ちます
（[pyproject.toml](../../pyproject.toml)）。本項目はそれらを狭めません。`scripts/**` も
`T20` / `S607` の無視をそのまま保ちます。

landing 前に `bajutsu/`・`tests/`・`demos/`・`scripts/` の4つのツリーすべてに対して8つの分類を
測定しました。その結果、`tests/**` には上記の理由により `SLF` と `ARG` という2つの新しい一括無視が
必要だとわかりました。`bajutsu/` の外で見つかった `PTH`・`RET`・`PLW` の小さな残りは、上の各項目で
説明したとおり、無視ではなく修正します。`demos/**` と `scripts/**` には新しい一括無視は必要ありません。

## 検討した代替案

- **`PL` プレフィックス全体を採用する**：却下します。`PLC0415` だけで526件中258件を占め、本
  コードベースの遅延 import という意図的な慣習にほぼ全面的に反しています。本項目のように `PLE` を
  独自のプレフィックスで選択すれば、この雑音を抱え込まずに、持つ価値のある層だけを取り込めます。
- **ruff と並べて専用の Pylint、Dlint、あるいは `hacking` を導入する**：却下します。これは、
  BE-0067 が専用の Bandit 導入ではなく ruff の `S` を選んだことと整合します。ruff はそれぞれの
  有用な部分をすでに再実装しています。Pylint のルール群には `PL*` が、Dlint が加えるはずの
  セキュリティ lint の役割にはすでに `S` が対応します。2つ目のツールを入れても、ゲート自身の
  linter を重複させるだけで、実際のギャップを埋めることにはなりません。`hacking` は OpenStack の
  プロジェクト規約を対象としたものであり、ここには当てはまりません。
- **`TRY003` を有効にして呼び出し箇所ごとに抑制する**：却下します。438件では、呼び出し箇所ごとの
  `# noqa` が、それが説明するはずの例外送出コードの件数を上回ってしまいます。理由を書いたコメント
  付きでルールそのものを1か所で抑制するほうが、雑音なしに同じ判断を伝えられます。
- **`ARG002` の指摘をリポジトリ全体のアンダースコア接頭辞の慣習（`_backend_specific_arg`）へ
  まとめる**：却下します。あるバックエンドが無視している Protocol の引数すべてをリネームする
  と、見た目だけの変更のために実装のシグネチャすべてに手を入れることになります。その引数を使わない
  実装1か所に絞った `# noqa` のほうが小さく、その場で理由を示せます。

**ログ**

- 8つの分類すべてを、チェックリストの並び順どおりに1分類1コミットで投入しました
  （[#1761](https://github.com/bajutsu-e2e/bajutsu/pull/1761)）。上の件数は投入時点で計測した
  実測値です。提案執筆時の数値からわずかに増えています。`ARG002` は94件から98件、`TRY004` は
  10件から11件、`tests/` の `PLW1510` は5件から7件になりました。提案を書いたあとにコードが
  増えたぶんです。*詳細設計* が想定していた扱いと異なる判断を3つ採りました。いずれも、
  ルールを有効にしてはじめてコードが示した理由によるものです。
  - **`SLF`** はクラスの内部状態を1件も検出しませんでした。38件はすべて、モジュールレベルの
    プライベートな補助シンボルへのモジュール跨ぎの参照です。内訳は `adb._real_run` と
    `_checked_serial`、`simctl._real_run`、`base._contains`、`readiness._await_ready` と
    `_await_boot`、`intervals._spawn`、`_yaml._Loader` です。しかもいくつかは**公開関数**の
    デフォルト引数として使われており、すでにモジュールの契約面の一部になっています。したがって
    アンダースコアを外して公開名にすることが、詳細設計の言う「narrow public accessor を出す」に
    あたります。7つのうち6つはこの方針で公開名にしました。例外は `_yaml._Loader` です。
    `pyproject.toml` の `S506` をファイル単位で無視する設定は、このモジュールの `yaml.load` の行を
    `main` とバイト単位で同一に保つために置かれています。`main` では CodeQL が同じ
    `py/unsafe-deserialization` の指摘を誤検出として却下済みです。コードスキャンの却下は
    指摘元の行そのものをハッシュした指紋に紐づくため、クラス名を変えると却下済みの指摘が
    新しい未処理の指摘として開き直します。そこで `_Loader` は非公開のまま残し、モジュール跨ぎの
    参照3箇所に `# noqa` を付けました。`oplog` が `logging.Handler` に付ける名前空間つきマーカー
    `_bajutsu_oplog` と、`theme_editor` が意図的にキャッシュを破棄する箇所と合わせて、`# noqa` は
    全部で5件です。
  - **`TRY004`** は11件すべてについて、`TypeError` へ変えず現在の例外型を `# noqa` 付きで残し
    ました。うち10件は外部から受け取ったペイロードを検証する箇所です。JSON や YAML の文書、
    HTTP レスポンスの形がそれにあたります。型が違うことはデータの誤りであって、呼び出し側が
    誤った型を渡したことではありません。しかも複数の関数が `Raises: ValueError` を docstring に
    明記しており、呼び出し側は `ValueError` を捕捉しています。`TypeError` へ変えれば、そうした
    ハンドラーが黙って壊れます。残る1件は `serve/_cli_flags.py` にあります。ペイロードではなく、
    typer のコマンドレジストリの不変条件を守るものです。他の10件の理由を流用せず、そのことを
    `# noqa` に書いています。
  - **`TRY300`** は17件のうち15件について、return を `else` ブロックへ移しました。残る2件は
    `try` の中に残しています。`notify._mask_url` は、返している f 文字列そのものがガードの
    保護対象だからです。ステップのディスパッチャーは、そのブロックが4つの分岐から return して
    おり、最後の1つだけを `else` へ持ち上げると、残る3つが成功パスではないかのように読めて
    しまうからです。

  `bajutsu/` にある `ARG002` の98件のうち、97件はインタフェースが要求する引数です。どの型を
  満たすためかを書いた `# noqa` を付けて残しました。例外は
  `XcuitestEnvironment._create_replacement` の1件です。クラス内から2箇所が呼ぶだけの非公開
  メソッドで、プロトコル上の義務もなく、`eff` は単に使われていません。そのため
  `_write_pixelmatch_diff` の `h` や `_run_if` の `clock` と同じく削除しました。
