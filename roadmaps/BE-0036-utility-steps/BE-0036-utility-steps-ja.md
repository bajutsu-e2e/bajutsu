## はじめに

`http` ステップは、ランナーから HTTP リクエストを発行し、レスポンス本文を `vars.*` 名前空間へ保存します。用途は、テストデータの準備、webhook の起動、後続ステップが必要とする値の取得です。この項目は当初、ワンタイムパスワード（OTP）／二要素認証（2FA）とメールの側方チャネルステップも対象にしていました。これらは別の提案へ分割しました（[参考](#参考)を参照）。

## 動機

run はしばしば、UI だけでは供給できない値に依存します。バックエンドからのトークン、API で仕込むフィクスチャ、run が起こさなければならない webhook などです。リクエストを発行してその結果を run に取り込む手段がなければ、こうしたケースは手作業のセットアップに頼るか、省かれてしまいます。手作業のセットアップは再現できません。`http` ステップはこの欠落を埋めます。シナリオが値を取得し、後続のステップへランタイム変数として決定的に渡せるようになります。

## 詳細設計

`http` ステップは、アプリではなくランナープロセスからリクエストを発行します。レスポンス本文はランタイム変数として保存され、後続で `${vars.*}` 補間に使えます。

```yaml
- http: { method: POST, url: "${secrets.API}/login", body: "...", status: 200, saveBody: token }
- type: { text: "${vars.token}", into: { id: auth.token } }
```

フィールドと契約は次のとおりです。

- **`method`**（既定 `GET`）、**`url`**（`http` か `https` のみ）、任意の **`headers`** と **`body`**。
- **`status`**：指定すると、ステップがレスポンスのステータスを照合し、食い違えば失敗します。
- **`saveBody`**：レスポンス本文の**全体**を `vars.<saveBody>` として保存します。本文全体ではなく JSON パスや正規表現で単一フィールドを抽出する機能は、自然な続きです。今後の作業に挙げており、まだ未実装です。
- このステップは*取得ユーティリティ*です。アプリ自身のトラフィックを観測する、アプリ内の `request` アサーションや `mocks` とは別物です。同じ PR では、デバイスをリセットする補助ステップ `clearKeychain` と `clearClipboard` も追加しました。

prime directive は次のように保たれます。

- **run パス上に LLM を置かない。** `http` ステップは決定的なリクエストで、その結果は機械的なルール（ステータスチェック、本文の取得）で取り込まれます。合否判定は引き続き、機械でチェックできるアサーションだけから得られます。run／CI ゲートは AI 非依存のままです。
- **決定性。** リクエストは即時です。失敗したリクエストやステータスの食い違いは、黙った誤った値ではなく、きれいなステップ失敗として表れます。
- **アプリ非依存。** ステップとその配線はアプリをまたいで同一です。異なるのはエンドポイントとシークレット（config／`${secrets.*}`）だけです。シークレット（API のベース URL、トークン）は `${secrets.X}` として参照し、証跡では自動でマスクされます。そのため、シナリオはトークンを保持し、値は保持しません。
- **codegen。** `http` ステップはアプリではなく bajutsu ランナーで動き、XCUITest 等価物がありません。そのため codegen は、ラベル付きの `// TODO` を出力します（[BE-0026](../BE-0026-shrink-unsupported-syntax/BE-0026-shrink-unsupported-syntax-ja.md) に従います）。

## 検討した代替案

- **任意のコマンドを実行して値を生成する汎用 `shell`／`exec` ステップ。** 柔軟性は最大です。ただし、何でも実行できるため、シナリオが可搬でなくなり、レビューもできなくなります。さらに、テストが CI ホストに結びつきます。少数の目的特化で監査可能なステップを優先し、却下します。
- **`mocks`／`request` アサーションで値を観測する。** これらはアプリ*自身*のトラフィックをスタブしたり観測したりします。テスト自身が帯域外で値を取得しなければならない場合には役立ちません。置き換えではなく補完として維持します。
